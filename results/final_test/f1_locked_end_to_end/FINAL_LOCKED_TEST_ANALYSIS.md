## 15. Reproducibility notes

Regenerating three validation reports in the pre-test dry run gave identical text for two and a semantically equivalent rewording for one, so local GPU generation is not bitwise reproducible. The validation dry run reproduced every stored result; for the locked run the prompt and request hashes of all 486 generations equal their rebuild (see `f1_final_integrity_report.json`).

## 16. Limitations

- IU X-Ray labels are MeSH-derived and incomplete, the classifier is applied out of domain (CheXpert to IU), one small quantised model was run once with greedy decoding, the bootstrap resamples studies (no patient identifier), and nothing here shows clinical benefit; the system is a research prototype.
- The classification population is the subset with a usable mapped truth; the 28 studies without a frontal image and the studies without a reference are not evaluable end to end.
- Rare-finding and per-class results rest on very small counts; some classes have one to five test positives and one has none.
- The abnormal-routing normal-prose inconsistency of the frozen G1 prompt remains and is reported, not repaired.
- Validation numbers for the comparison were computed with the same code on the IU validation partition, which was also used during development of earlier stages; test minus validation is therefore a generalisation check and not an independent re-selection.

## 17. Conclusion

The frozen end-to-end system was evaluated once on the locked test set without post-test changes. Its test estimates are close to validation for retrieval (Jaccard@5 0.558 versus 0.557), somewhat lower for finding recall and F1, and the decision coverage fell from 0.937 to 0.891 because more studies were indeterminate. Final model development is closed.
