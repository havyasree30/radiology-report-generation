# C3: per-class threshold optimisation and operating-point evaluation

_Generated by `scripts/c3_write_report.py` from the stored artifacts. No model was trained or re-run: the canonical C2-B validation scores were verified and reused. The locked test split was not opened._

## 1. Objective

C2 asked which loss **ranks** positives above negatives better. C3 asks a different question: **at what score should each of the 14 findings be called positive?**

A single 0.50 cut-off is not automatically appropriate here, for three reasons:
- The 14 outputs are independent sigmoid scores of a multi-label model. Nothing ties them to a common scale.
- Prevalence ranges from 1.3% to 56%, so an equally calibrated score would sit far below 0.50 for rare findings.
- Loss weighting (here √-weighted BCE) changes the score scale in a class-dependent way.

The task therefore replaces the universal 0.50 with class-specific thresholds learned on the validation split. **AUROC and AUPRC are threshold-independent and therefore remain unchanged by threshold selection.** The C2-B values are reproduced below only as a check.

## 3. Method

Decision rule: a finding is positive when `score >= threshold`. Candidate thresholds are the distinct validation scores of that class, evaluated on valid (non-uncertain) entries only. Counts are integers, so ties are decided exactly.

- **Default 0.50.** Applied to every class as the baseline.
- **Youden J (primary).** `J = Sensitivity + Specificity − 1 = TPR − FPR`; threshold = argmax J per class. Tie rule: higher sensitivity, then higher threshold. If J ≤ 0 everywhere, or a class has no positives or no negatives, the threshold is reported as undefined instead of being invented.
- **F1-optimal (secondary).** `F1 = 2TP / (2TP + FP + FN)`; threshold = argmax F1. Tie rule: higher recall, then higher threshold. It is a sensitivity analysis only.
- **Patient bootstrap.** 1,000 resamples of the 9,530 validation patients with replacement (all of a patient's images move together; the same resample is used for all 14 classes; seed 42). The Youden threshold is recomputed in each resample.
- **Pre-declared rules (written into the code before any C3 number was seen).** Threshold flagged low if < 0.1, high if > 0.7, near 0 if < 0.02, near 1 if > 0.98. Bootstrap interval flagged unstable if its 95% width > 0.2 or > 1.0× the bootstrap median. Rare/common groups are the ones used in C2.

What Youden does, and what it costs:
- **Recall:** macro recall 0.448 → 0.754; balanced accuracy 0.672 → 0.734.
- **Costs:** macro precision 0.426 → 0.321, macro specificity 0.897 → 0.713, and macro F1 0.430 → 0.399.
- **So Youden is not an F1 improvement.** It buys sensitivity with false positives. Balanced accuracy rises in 14 of 14 classes (by +0.001 to +0.180); the gain is negligible (≤ +0.004) for Lung Opacity, Pleural Effusion, Support Devices. F1 falls in 10 of 14 classes.

## 12. Limitations

- **Thresholds are optimised on the same validation data they are evaluated on.** All threshold-dependent numbers here are **validation operating-point performance**, optimistic by construction. They are not independent test estimates.
- **The locked test split was deliberately not opened.** The task allows applying frozen thresholds to an untouched test set once. I did not, because the loss choice is still provisional (single-seed screening; multi-seed confirmation is pending). Spending the one-shot test now would leave nothing untouched for the final model. This is flagged for your decision.
- **Rare-class thresholds** rest on few validation positives (Pleural Other: 381) and are low relative to their own interval; precision at those operating points is very low (§7).
- **Sigmoid scores are not calibrated probabilities.** Do not display them as percentages or compare absolute levels across classes without separate calibration work.
- **Blank labels are scored as negatives**, so some counted false positives may be findings that were present but unreported; precision is therefore a lower bound.
- **C2 loss selection is provisional**, based on one seed per arm and gaps comparable to epoch-to-epoch noise. A different final loss changes the score scale and would require re-fitting every threshold.
- **Youden ignores prevalence.** Per-class thresholds are fitted independently; no cross-class consistency is enforced (see No Finding, §9).

## 13. Decision

Carry the **14 validation-derived Youden J thresholds** (`thresholds_youden.json`) forward as the **provisional** operating points for the classification pipeline, as planned. The data revealed no per-class pathological edge case (every threshold is defined and inside (0, 1), and none is flagged unstable by the declared rule). The file reloads bit-exactly and the downstream per-image file is `validation_predictions_youden.csv.gz`.

Two consequences must stay visible to downstream work:
1. The Youden operating points over-call: predicted findings per image are well above the true count, rare-class precision is 0.03–0.13, and the No Finding contradiction rate is high (§9).
2. The F1-optimal thresholds (`thresholds_f1.json`) give a markedly different, more conservative operating point. Choosing between them is a precision-vs-recall policy decision.

Whether to adopt a prevalence- or precision-aware rule, or a No Finding consistency rule, is **not decided here** and would be a separate, approved experiment. Nothing further was started.
