# R1: retrieval baseline and vision-to-retrieval evaluation

_Generated by `scripts/r1_07_write_docs.py` from the R1 artifacts. Retrieval-validation queries only; the locked retrieval-test split was not opened. The frozen classifier was not modified._

## 1. Objective

Establish a defensible retrieval baseline for `Chest X-ray → frozen classifier → finding query → retrieval → RAG → preliminary report`, and measure how much retrieval quality is lost between a perfect finding query (oracle) and the query produced by the frozen classifier on IU X-Ray, including whether a precision-aware query gate helps. RAG and report generation are not part of R1.

## 2. IU X-Ray dataset preparation

Local files were used (nothing downloaded): 3,851 reports, 7,466 listed images (3,818 frontal, 3,648 lateral; 7,470 files on disk, 4 not listed), 3,405 studies with more than one image and 162 studies without a frontal image. After cleaning, 3,337 reports have a Findings section, 3,820 an Impression, 3,331 both and 25 neither. Terminology available: MeSH indexing (121 distinct terms; 1,379 studies indexed `normal`) and a Problems field that repeats the MeSH terms. The inventory is `iu_xray_dataset_inventory.json`.

Retrieval text = cleaned Findings + Impression (Impression or Findings alone when only one exists; duplicated headings, markup and the `XXXX` de-identification placeholder removed; Indication and Comparison excluded as metadata). Original text is stored separately in `retrieval_corpus.csv`; no text is rewritten or generated.

## 3. Leakage-safe retrieval split

The Phase 1 study-level split is reused, not recreated (project rule: no ad hoc re-splitting). It is the preferred 70/15/15 split (seed 42), its unit is the report id so every image of a study stays together, and it stratifies on MeSH normal versus other. Reference corpus: 2,675 training studies with text. Retrieval-validation queries: 578 studies (1,113 images). Locked retrieval test: 578 studies (1,115 images), listed by id only and never read.

Checks (status PASS): corpus ∩ validation = 0, corpus ∩ test = 0, validation ∩ test = 0; studies whose images span more than one split = 0; image files in more than one split = 0. Self-retrieval check: 22,380 retrieved rows, 0 equal to the query study, 0 from validation, 0 from the locked test split (status PASS). Identical report text appears across different studies (generic normal reporting): 107 validation reports have an exact text copy in the corpus; this is not self-retrieval, and the primary-set sensitivity analysis below excludes such queries.

## 4. Finding mapping

IU MeSH terms were mapped to the frozen 14-class vocabulary with explicit rules (`iu_finding_mapping.json`): direct term mappings from the Phase 1 lexicon, two qualifier-conditional rules (Cardiac Shadow/enlarged → Cardiomegaly; Thickening/pleura → Pleural Other), and an explicit list of ambiguous terms that are **not** mapped (Pulmonary Congestion, Density, Mediastinum, other Cardiac Shadow and Thickening qualifiers). Terms outside the vocabulary (spine, aorta, granuloma, emphysema and others) are stored as unmapped. No IU term maps to Enlarged Cardiomediastinum. A study's evaluation set is its mapped abnormal findings, or {No Finding} if it is indexed normal and has none; a study with neither has no usable representation. Of 578 validation studies, 403 have an evaluation set (207 normal, 196 with a mapped abnormal finding) and 175 are excluded from evaluation; 382 of the 403 have a frontal image, and 358 of those have a non-empty classifier query (the primary paired set; 24 empty).

## 5. Dense retrieval

`sentence-transformers/all-MiniLM-L6-v2` (revision `1110a243fdf4`, not fine-tuned) embedded the 2,675 corpus reports; the embedding dimension was verified programmatically as 384; vectors are L2-normalised (norm range 1.000000–1.000000) and stored in a FAISS `IndexFlatIP` (inner product = cosine). 2 corpus texts exceed the encoder limit of 256 tokens and are truncated. Index, id mapping and metadata are saved under R1.

## 6. Lexical baseline

Okapi BM25 (k1 = 1.5, b = 0.75), implemented in-house; lowercase alphanumeric tokens, no stop-word removal or stemming; ties broken by corpus order; vocabulary 1,794 tokens. No hyper-parameter was tuned.

## 7. Query construction

Query phrases are fixed before evaluation (`src/retrieval/queries.py`) and emitted in a fixed class order: oracle = the study's mapped finding names (never the report text); classifier all-positive = every frozen-positive finding among the 13 non-No-Finding classes; if none and No Finding is positive, the fixed query `no acute abnormality`; if neither, the query is recorded as empty (no finding is invented). The classifier query uses the first frontal image of the study, the frozen preprocessing, checkpoint, Platt calibrators, C4 thresholds and No Finding rule; this is an external, domain-shift application, and nothing was tuned on IU X-Ray.

**Precision-aware gating.** Gates were derived on the CheXpert classifier validation set only (`precision_aware_query_gates.json`): candidates are calibrated-probability quantiles of each class's frozen positives; the criterion is F0.5; a gate is adopted only if its cross-fitted (5-fold, patient-level) F0.5 gain has a bootstrap 95% lower bound above zero. A gate is not a classifier threshold: binary decisions are unchanged. Positives failing the gate are kept as low-confidence metadata and excluded from the query; if no abnormal finding survives, the normal query is used when No Finding is positive, otherwise the strongest classifier-positive finding is used and marked as a fallback.

Gates were adopted for 12 of 13 findings; no gate for Pleural Other (no stricter candidate with a reliable out-of-fold gain). Across adopted gates precision rose by +0.058 to +0.138 and recall fell by 0.096 to 0.325 (absolute, validation set).

## 8. Oracle retrieval results

Primary paired set: 358 queries (all three policies evaluated on the same studies). Relevance is finding agreement with the study's true finding set; Jaccard@K is the mean over the K retrieved reports; nDCG uses Jaccard as graded gain with the ideal ranking taken over the whole corpus. With oracle queries, dense retrieval reaches Jaccard@3 0.805 (95% CI 0.778 to 0.832) and nDCG@3 0.809; lexical retrieval 0.787 (95% CI 0.755 to 0.816) and 0.793. Both are far above the random expectation (0.213). Dense minus lexical Jaccard@3 is +0.018 (95% CI -0.002 to +0.038). Hit@3 (retrieved report has exactly the true finding set) is 0.906 (dense) and 0.818 (lexical). Binary relevance is defined only as an exact finding-set match, a parameter-free criterion; Recall@K is omitted because the number of relevant reports varies from a handful to over a thousand between queries, which makes it uninformative.

## 9. Frozen-classifier retrieval results

With queries built from the frozen classifier, Jaccard@3 falls to 0.514 (95% CI 0.465 to 0.560) (dense) and 0.533 (95% CI 0.484 to 0.577) (lexical), i.e. 0.291 and 0.254 below the oracle (paired 95% intervals exclude zero). The retriever is therefore not the main bottleneck; the upstream query is. Query-faithfulness (agreement with the query's own findings) is higher than agreement with the truth (dense all-positive Jaccard@3 0.691 against the query versus 0.514 against the truth), consistent with retrieval following the query while the query is wrong about the study.

**Main question: does precision-aware finding selection improve retrieval compared with passing every classifier-positive finding?** No consistent improvement was found. For Jaccard@3 the paired difference (gated minus all-positive) was +0.006 (95% CI -0.008 to +0.021) with dense retrieval and -0.003 (95% CI -0.015 to +0.010) with lexical retrieval; for nDCG@3 it was +0.006 (95% CI -0.009 to +0.021) and -0.008 (95% CI -0.020 to +0.006). The only interval excluding zero was for lexical jaccard_truth@1 (a decrease). The gate shortened queries from 1.50 to 1.16 findings on average and removed 251 of 448 frozen-positive finding instances across the 551 classified validation studies, but 18.7% of studies then relied on the strongest-positive fallback. The share of queries whose finding set exactly equals the truth changed from 40.3% to 43.5% (eligible studies). This is a downstream systems comparison; it does not change classifier performance.

## 10. Top-K analysis

With oracle queries the finding Jaccard changes little across K (range 0.038 for dense; dense 0.797, 0.805, 0.809, 0.771 at K = 1, 3, 5, 10), while the union coverage of the true findings rises from 0.855 (K=1) to 0.964 (K=3), 0.971 (K=5) and 0.977 (K=10); most of the gain is reached by K=3. With all-positive classifier queries the Jaccard range is 0.012, but coverage keeps rising (0.574, 0.646, 0.676, 0.814), and the share of retrieved reports with zero finding overlap stays near 37.9% at every K. Redundancy grows with K: with dense oracle retrieval 34.8% of the top-3 and 47.3% of the top-10 reports have text identical to another retrieved report (templated normal reports).

Top-3 is a defensible default for oracle-quality queries (most of the achievable coverage, no Jaccard loss) but it is not shown to be optimal: for classifier-driven queries coverage still improves at larger K, redundancy grows with K while the share of retrieved reports without finding overlap stays roughly constant, and the choice of K is deferred to R2 where it can be judged on generated reports.

## 11. Error analysis

Using the dense retriever and the top-1 report (`retrieval_error_analysis.csv`; outcome = exact finding-set match → good, partial overlap → partial, none → poor): oracle queries give 245 good / 86 partial / 27 poor; all-positive classifier queries give 158 / 67 / 133. Of the 200 non-good classifier-query cases, 190 trace to a classifier query that differs from the true finding set (normal-versus-abnormal 77, missing and extra findings 70, extra findings only 33, missing findings only 10) and 10 to retrieval mismatch despite a correct query; 14 of the non-good cases involve a study with an ambiguous (unmapped) MeSH term, so the truth may be incomplete there. The failures are therefore dominated by the upstream query. These are descriptive; nothing was changed on the basis of examples.

## 12. Domain-shift observations

On 551 IU validation frontal images (no image failed validation) the frozen classifier predicted a mean of 0.81 abnormal findings per study; the mapped IU truth averages 0.75 on the eligible studies (predicted 0.95 on the same studies). No Finding was predicted for 48.8% of studies against 51.3% indexed normal (precision 0.777, recall 0.730, F1 0.753); 49 studies (8.9%) produced an empty query. Largest over-prediction relative to IU truth: Fracture (17.2% predicted vs 2.4%); Consolidation (4.4% predicted vs 1.0%); Pneumonia (8.5% predicted vs 2.6%). Largest under-prediction: Support Devices (2.5% vs 9.2%); Cardiomegaly (6.2% vs 13.6%); Atelectasis (5.4% vs 11.0%). Enlarged Cardiomediastinum was predicted for 7.1% of studies but has no IU mapping to compare against. Macro agreement over the 13 abnormal findings is precision 0.313, recall 0.449, F1 0.297; this is descriptive, the IU truth treats unmapped as absent (precision is a lower bound), and nothing was tuned.

## 13. Limitations

- IU truth is derived from MeSH indexing mapped to 14 classes: 175 of 578 validation studies have no usable representation, Enlarged Cardiomediastinum cannot be evaluated, and several classes have very few IU positives (e.g. Edema 5, Consolidation 4, Pneumothorax 4 in the primary set), so per-class conclusions are not supported.
- The primary evaluation set is dominated by normal studies (187 of 358), for which finding agreement is easy, and templated reports are common (see the duplicate-text rate).
- Finding agreement is a proxy for usefulness as a RAG reference; it does not measure whether a retrieved report is clinically appropriate or whether a generated report would be correct.
- Query phrases are minimal finding names; no query expansion was tried, which may handicap lexical matching for terms such as support devices. Retrieval hyper-parameters were not tuned.
- IU has no patient identifier, so split independence is at study level; the same patient may appear in several studies.
- The classifier was applied to IU as an external domain; its behaviour there was not tuned and its precision is limited (see C6). Gates were derived on CheXpert, not IU.
- Confidence intervals resample queries (studies); they do not include classifier, embedding-model or mapping uncertainty.
- Only retrieval-validation queries were used; locked-test results are not available.

## 14. R1 conclusion

A leakage-safe, reproducible retrieval baseline is in place. Both retrievers recover the true findings well when given oracle finding queries (Jaccard@3 0.805 dense, 0.787 lexical, with no reliable difference), so retrieval itself is not the limiting component on this corpus. With queries from the frozen classifier the agreement drops to about 0.514–0.533, identifying the upstream finding query as the bottleneck. Precision-aware gating, derived on validation data without changing the classifier, did not give a reliable improvement over passing all frozen positives. Top-3 is a defensible default for oracle-quality queries (most of the achievable coverage, no Jaccard loss) but it is not shown to be optimal: for classifier-driven queries coverage still improves at larger K, redundancy grows with K while the share of retrieved reports without finding overlap stays roughly constant, and the choice of K is deferred to R2 where it can be judged on generated reports. R2 has not been started.
